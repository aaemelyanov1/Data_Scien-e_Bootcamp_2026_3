# Bot Detection Challenge

Решение задачи классификации ботов по логам событий Авито. Код воспроизводимый, зависимости зафиксированы, seed везде 0.

## Содержимое

- solution.ipynb - основной код в виде ноутбука
- metric.py - официальная метрика precision_at_recall, ей же считается локальный скор
- quickstart.ipynb - слабый baseline из условия, не тронут
- requirements.txt - зависимости с точными версиями
- submission.csv - финальные предсказания для test.csv

## Окружение

Python 3.14.7 (зафиксировано в .python-version и kernelspec ноутбука).

## Структура решения

- FeatureEngineer - единый класс с переключаемыми группами признаков (basic, temporal, bigram, graph, ua_semantic)
- Expanding Window CV на 3 временных фолдах
- Optuna с вложенным CV для каждой модели отдельно
- Сравнение rank-average блендинга и вложенного стекинга
- Финальные скоры через ordinal ranks

## Ключевые моменты

- Фильтр по окну наблюдения обязателен: captcha_shown лежит за пределами окна и на тесте этих событий нет
- Графовые признаки нормализованы на медиану пула, иначе разваливаются на тесте из-за разного размера выборок
- Словарь биграмм и target encoding UA строятся только по train-части фолда
- Дубликаты событий удаляются осознанно
- Метрика не умеет делить равные скоры, поэтому используется rankdata с method='ordinal'

## Результаты

Локальный pooled OOF около 0.73, на лидерборде precision@recall>=0.70 = 0.89. Константный ответ давал бы 0.094. Основной вклад дали графовые признаки, биграммы событий и расширение пространства поиска гиперпараметров.

## Ограничения

- Графовые признаки трандуктивны по природе (пул строится по всему events.csv.gz)
- UA-семантика дала небольшой прирост - боты хорошо мимикрируют под обычные браузеры
- Метрика шумная: bootstrap std на одном фолде около 0.07, поэтому локальные цифры имеют большой доверительный интервал
